# M2d "Crowd" Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Group chats grown from DMs (owner, remove and ban, rename, host a table with everyone), one chat line (`#lobby` plus your conversations), `#critical-mass` retired, diary announcements in `#lobby`, and an agent front door a plain HTTP fetch can find.

**Architecture:**
- **Channel and data:** a group is a channel `grp:<id>` in the existing `messages` table. Three new tables hold the group, its members (each with their own join point, read position and closed flag) and its bans.
- **`GroupManager`:** a new manager in `apps/server/src/core/groups.ts`, which plugs into `CommunicationManager` through hooks, the same way `DmManager` does. It makes the membership, visibility and delivery decisions; comms stores and pushes.
- **Web:** the conversation tabs (DMs and groups) move onto the same line as `#lobby` (or Table talk and The rail), and a conversation menu carries Add someone…, Group settings, Host a table with everyone, and Leave.

**Tech Stack:** Bun, TypeScript, Hono, Drizzle (Postgres/PGlite; migrations with `drizzle-kit generate`), SvelteKit (Svelte 5 runes), Playwright.

**Spec:** `docs/superpowers/specs/2026-09-30-m2d-crowd-design.md`

## Global Constraints

- Group channel: `grp:<id>`, where the id comes from `newId('g')`, giving `g_<16 hex>`.
- `GROUP_MAX_MEMBERS`: default 8, held to 2–50, with a warning at startup when out of range.
- Group name: 1–32 characters after trimming. It must pass both `containsSlur` and `containsProfanity`. Error codes: `BAD_NAME` (400) and `NAME_FILTERED` (400).
- A new member sees only messages with `id > first_message_id`. `first_message_id` is the largest `messages.id` in the whole table at the moment they joined (0 if the table is empty).
- Only the owner can remove and un-ban. Any member can add and rename. When the owner leaves, ownership passes to the member with the earliest `joined_at`, ties broken by identity id.
- The group ends when the last member leaves: `ended_at` is set and its bans are deleted.
- System lines use this exact wording:
  - `@a started a group with @b and @c.` (with one other person: `@a started a group with @b.`)
  - `@a added @b.`
  - `@a left.`
  - `@a was removed.`
  - `@a named this group "X".`
  - `@b is the owner now.`
- Errors, with their messages:
  - `GROUP_FULL` 409: "This group is full (N people)."
  - `ALREADY_MEMBER` 409: "@x is already in this group."
  - `NOT_MEMBER` 403: "You're not in this group."
  - `NOT_OWNER` 403: "Only the group's owner can do that."
  - `GROUP_BANNED` 403: "@x was removed from this group."
  - `BLOCKED` 403: the DM wording.
  - `HOUSE_AGENT` 409: "The Bouncer reads reports, not chats."
  - `NAME_FILTERED` 400: "Pick a different name for the group."
  - `BAD_NAME` 400: "A group name is 1–32 characters."
  - `TOO_MANY_FOR_GAME` 409: "Too many for <Game> (N seats)."
  - `NO_GROUP` 404: "There is no such group."
  - `NO_CHANNEL` 404, for `#critical-mass`: "#critical-mass is retired; talk in #lobby."
- Inbox events:
  - `chat.group {message}`
  - `group.changed {groupId}`
  - `group.gone {groupId, reason: 'removed' | 'left'}`
  - `group.read {groupId}`

  **A ruling on the spec:** `group.changed` carries only `groupId`, and clients re-read `GET /api/groups/:id`, rather than carrying the whole group. The group payload is per-viewer (unread count, hidden, bans), so one shared payload can't be right for everyone. The Task 9 docs describe it this way, and Task 2 updates the spec line.
- The web: one tab line, with no wrapping at 400 px. After 4 conversation tabs the rest fold into **More ▾**. The Visibility control shows **Private**, disabled, with "Public rooms are coming."
- Commits end with a blank line, then `Co-Authored-By: Claude Opus 5.5 (1M context) <noreply@anthropic.com>`, and no other Co-Authored-By.
- `bun run verify` is green at the end of every task. Run it in the foreground only, and leave nothing running.
- Known flakes: `HANDLE_FILTERED` random test handles, and `e2e/dms.e2e.ts:43`. If one of those is the only failure, name it and rerun once.

## Review Focus

1. **An added person reads history.** Someone added later must not see earlier lines through any door: `GET /api/chat/grp:<id>`, `GET /api/groups/:id` (`last`), the unread count, or the WebSocket. Task 3 tests all four.
2. **A removed person keeps receiving.** After removal, no `chat.group`, no socket push and no read. A socket that stays open must not keep getting lines, and delivery is computed per message from current members. Task 3 tests it.
3. **The owner leaves as the last member.** The group ends, bans clear, and nobody can add to it. Task 2 tests it.
4. **The same person twice in `with`, or yourself in `with`.** `POST /api/groups {with:["ann","ann","me"]}` de-duplicates, and refuses yourself with `SELF`. Task 2 tests it.
5. **A system line in a group.** `postSystem` must reach members' sockets and must not raise unread counts, or every rename would light every tab. Task 3 tests it.

/** GROUP_MAX_MEMBERS from the environment: 8 by default, held to 2–50. */
export function clampGroupMax(raw: string | undefined, warn: (m: string) => void): number {
  if (raw === undefined || raw.trim() === '') return GROUP_MAX_DEFAULT;
  const n = Number(raw);
  if (!Number.isFinite(n)) {
    warn(`[main] GROUP_MAX_MEMBERS=${raw} is not a number; using ${GROUP_MAX_DEFAULT}.`);
    return GROUP_MAX_DEFAULT;
  }
  const held = Math.min(GROUP_MAX_MAX, Math.max(GROUP_MAX_MIN, Math.round(n)));
  if (held !== n) warn(`[main] GROUP_MAX_MEMBERS=${raw} is outside ${GROUP_MAX_MIN}–${GROUP_MAX_MAX}; using ${held}.`);
  return held;
}

The rules each method must follow (the tests pin them):
- `create(me, raw)`:
  - `raw` must be a non-empty array of strings, else `BAD_FIELD` 400 ("Send {\"with\": [\"handle\", …]}.").
  - Bare and de-duplicate the handles.
  - Resolve each through `this.target(me, handle)` (below). The total, you included, must be ≤ max, else `GROUP_FULL`.
  - Insert the `chat_groups` row, with `id = newId('g')` and `ownerId = me.id`.
  - Insert a member row for each person, with `firstMessageId = await this.newestMessageId()`.
  - Post the system line.
  - Deliver `group.changed` to every member except `me`, so their lists refresh.
  - Return `this.get(me, id)`.
- `target(me, handle, group?)` (private), in this order:
  1. The handle resolves to someone who isn't released, else `NO_USER` 404 ("Nobody here goes by @x.").
  2. Not me, else `SELF` 400 ("You're already in it.").
  3. Not a house agent with role `mod`, else `HOUSE_AGENT` 409.
  4. If `group`: not already a member, else `ALREADY_MEMBER`.
  5. If `group`: not banned, else `GROUP_BANNED`.
  6. Blocks both ways, via `relations.blocks(target.id, me.id)` and `relations.blocks(me.id, target.id)`, with the DM messages, else `BLOCKED`.
- `add(me, groupId, handle)`:
  - `requireMember` (below).
  - Count the members; if the count is ≥ max, throw `GROUP_FULL`.
  - `target(me, handle, group)`.
  - Insert the member row.
  - Post the system line `@me added @them.`
  - Deliver `group.changed` to the other members.
  - Return `get`.
- `rename(me, groupId, raw)`:
  - `requireMember`.
  - Trim the name; it must be a string of 1–32 characters, else `BAD_NAME`.
  - `containsSlur(name) || containsProfanity(name)` means `NAME_FILTERED`.
  - Update, post the line, deliver `group.changed`, and return `get`.
- `remove(me, groupId, handle)`:
  - `requireMember`.
  - **Leaving** (the handle is yourself): delete your member row, post `@me left.`, and deliver `group.gone {reason: 'left'}` to yourself.
    - If nobody is left, set `endedAt`, delete the group's bans, and return `null`.
    - Else, if you were the owner, pick the next owner: the earliest `joinedAt`, ties by `identityId`. Update `ownerId` and post `@x is the owner now.`
    - Deliver `group.changed` to the rest, and return `null`.
  - **Removing someone else:**
    - You must be the owner, else `NOT_OWNER`.
    - The target must be a member, else `NOT_MEMBER` 403 ("@x isn't in this group.").
    - Delete their row, insert a ban (`bannedBy = me.id`), and post `@x was removed.`
    - Deliver `group.gone {reason: 'removed'}` to them and `group.changed` to the rest.
    - Return `get(me)`.
- `unban(me, groupId, handle)`: `requireMember`, and you must be the owner. Delete the ban row if present (it's idempotent). Deliver `group.changed` to yourself. Return `get`.
- `requireMember(me, groupId)` (private):
  - The group row exists and `endedAt` is null, else `NO_GROUP` 404.
  - The member row for `me` exists, else `NOT_MEMBER` 403.
  - Returns `{ group, member }`.
- `get(me, groupId)` means `requireMember`, then `this.info(me, group, member)`.
- `list(me)`: your member rows joined to groups not ended. Build `info` for each, then sort by `last?.id` descending (null last).
- `info(me, group, member)` (private):
  - The members are joined to identities in `joinedAt` order, each as `{ identity, joinedAt: iso, owner: id === group.ownerId }`.
  - `bans` is the full list for the owner, and `[]` for everyone else.
  - `last` is the newest line you can see (Task 3 routes it through history; for now, the newest `messages` row in the channel with `id > member.firstMessageId`).
  - `unread` is the count of messages in the channel with `id > max(firstMessageId, lastReadId)`, `system = false`, and an author other than me. Task 3 subtracts muted authors. Capped at 99.
  - `hidden`, and `maxMembers`.
- `read(me, groupId)`: set `lastReadId` to the newest message id in the channel (unchanged if none), deliver `group.read {groupId}` to yourself, and return `get`.
- `close(me, groupId)`: set `hidden = true`, and return `get`.
- `memberIds(groupId)`: the member identity ids of a live group, or `[]` if the group has ended or doesn't exist.
- `forget(identityId)`: for each group the person is in, run the leaving path, but without delivering to them (they're released).
- `newestMessageId()` (private): `select max(id) from messages`, or 0.

export function groupRoutes(core: Core): Hono<AppEnv> {
  const app = new Hono<AppEnv>();
  const g = core.groups;
  app.post('/groups', async (c) => {
    const who = me(c);
    const b = await body(c);
    return c.json({ group: await g.create(who, b.with) }, 201);
  });
  app.get('/groups', async (c) => c.json({ groups: await g.list(me(c)) }));
  app.get('/groups/:id', async (c) => c.json({ group: await g.get(me(c), c.req.param('id')) }));
  app.patch('/groups/:id', async (c) => {
    const who = me(c);
    const b = await body(c);
    return c.json({ group: await g.rename(who, c.req.param('id'), b.name) });
  });
  app.post('/groups/:id/members', async (c) => {
    const who = me(c);
    const b = await body(c);
    return c.json({ group: await g.add(who, c.req.param('id'), typeof b.handle === 'string' ? b.handle : '') });
  });
  app.delete('/groups/:id/members/:handle', async (c) => c.json({ group: await g.remove(me(c), c.req.param('id'), c.req.param('handle')) }));
  app.delete('/groups/:id/bans/:handle', async (c) => c.json({ group: await g.unban(me(c), c.req.param('id'), c.req.param('handle')) }));
